1 System Overview

FarmTrack Pro is a comprehensive farm management platform designed to digitize and streamline all aspects of livestock operations. It provides real-time dashboards, automated alerts, role-based access control, and a veterinary consultation module.

Key Objectives

  • Digitize livestock records — registration, health, vaccination, feeding
  • Automate alerts for low feed, offline feeders, overdue vaccinations, critical health
  • Enable role-based workflows for Admins, Farmers, Staff, Doctors, and HoDs
  • Provide analytics dashboards with species distribution, feed trends, and health metrics
  • Support veterinary consultations with appointment scheduling and prescription management

5 Authentication & Authorization Flow

Login Sequence

1
User enters credentials

Farmer ID + Password on the login page (or Admin Name + Password on the admin login page)

2
Frontend sends POST request

POST /api/auth/login or POST /api/auth/admin/login with JSON body

3
Backend looks up user in database

Searches by farmerId, name, or email in the users collection

4
Password verification with bcrypt

bcrypt.compare() validates the plaintext password against the stored hash (10 salt rounds)

5
JWT token generated & returned

jwt.sign({ id: user._id }, JWT_SECRET) — token returned with user object

6
Frontend stores token in localStorage

All subsequent API calls include Authorization: Bearer <token> header

Admin Registration Bootstrap

  • First admin: Created via POST /api/auth/admin/register with system ADMIN_PIN (default: admin123)
  • Subsequent admins: Requires a valid admin JWT token in the Authorization header
  • Regular users: Created by admins through the Staff Management panel with custom names and roles

8 Alert Engine Design

The alert engine automatically generates real-time alerts by analyzing live data from feeders, feed logs, vaccinations, and health records. Alerts are computed on-the-fly (not stored), ensuring they are always current.

⚠️
Low Feed Level — Triggered when feeder feed level drops below 30%
🔴
Feeder Offline — Triggered when feeder status = "Offline"
ℹ️
High Feed Usage — Triggered when feed log quantity exceeds 35 units
🔴
Overdue Vaccination — Triggered when due date has passed and status is "pending"
🔴
Critical Health — Triggered when health condition = "critical"

12 Security Measures

🔒 Password Hashing
bcrypt with 10 salt rounds — plaintext passwords are never stored
🎫 Token Authentication
JWT (JSON Web Tokens) for stateless session management
🌐 CORS Protection
Custom middleware restricts allowed HTTP methods and headers
✅ Input Validation
Server-side field validation on all endpoints before database writes
🖼️ Upload Security
Multer with 5MB limit and image MIME-type filtering
📌 Admin Bootstrap PIN
Required for first admin registration; subsequent admins need JWT
🚫 Self-Delete Protection
Admins cannot remove their own account to prevent lockout
🛡️ Error Handling
Malformed JSON body diagnostics with safe error messages

13 Key Design Decisions

DecisionRationale
Dual data store (MongoDB + JSON file) Allows deployment without MongoDB; JSON store serves as fallback for lightweight local use
User-Staff synchronization Every user account automatically creates a matching staff directory entry for consistent display
SPA architecture Single-page app with client-side routing provides instant navigation and smooth UX
Real-time alert engine Alerts computed on-the-fly from live data rather than stored, ensuring they are always current
Role-based but permissive access All authenticated users can perform most operations; admin-only actions require JWT validation
Glassmorphic login UI Animated water-drop background creates a premium, memorable first impression
